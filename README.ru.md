# Hidden Pairs: объединение ядер и ранговый ансамбль

Решение командного соревнования **[Week 03: Hidden Pairs](https://www.kaggle.com/competitions/week-03-hidden-pairs)** курса «Введение в машинное обучение» Университета Иннополис.

**Команда CHIMIN: private ROC-AUC 0.94832, 14-е место среди 94 строк итоговой таблицы.**

[English README](README.md) · [Ноутбук](solution.ipynb) · [Скрипт](solution.py)

## Задача и решение

Бинарная классификация по 512 анонимным неотрицательным числовым признакам. В train — 2 520 объектов, в validation — 560, в test — 1 116. Результат оценивается по ROC-AUC.

Основная модель **D v2** — одна SVC, обученная на взвешенной сумме пяти RBF-ядер. Каждое ядро описывает расстояния между объектами в своём представлении:

| Представление | Вес |
|---|---:|
| Исходные признаки после стандартизации | 0.288 |
| Квантильное преобразование к нормальному распределению | 0.288 |
| 64 компоненты PCA с whitening | 0.160 |
| Направление исходного вектора | 0.200 |
| Геометрические признаки относительно прототипов классов | 0.064 |

Геометрические признаки используют метки классов. Поэтому для train они строятся с внутренним cross-fitting: прототипы, которыми преобразуется объект, обучаются без этого объекта и его метки. Для validation/test применяется геометрическая модель, обученная на всём train.

Дополнительно обучаются две SVC: на 128 компонентах PCA исходных признаков и на 128 компонентах PCA после `log1p`. Перед обеими ветками применяется отсечение по 99.5-му процентилю, вычисленному только на train.

Финальное предсказание — **63% ранга D v2 + 27% ранга PCA128 + 10% ранга Log-PCA128**. Ранги позволяют объединить SVM с разными масштабами decision scores. Они вычисляются внутри всей оцениваемой выборки и не являются калиброванными вероятностями.

## Зафиксированный результат

| Проверка | ROC-AUC |
|---|---:|
| 5-fold CV, значение из итогового отчёта | 0.93805430 |
| Validation | 0.95454082 |
| Kaggle public | 0.94826 |
| Kaggle private | 0.94832 |

В сохранённом локальном запуске полное выполнение заняло 44.62 с, предсказание test — 2.75 с. Это историческое измерение на исходном компьютере. Список версий и сохранённый вывод доступны в [reports/original_run.txt](reports/original_run.txt); происхождение чисел — в [reports/recorded_results.json](reports/recorded_results.json).

Validation многократно использовалась для сравнения идей, поэтому её результат не считается оценкой на полностью нетронутой отложенной выборке. Небольшой выигрыш CV сам по себе не доказывает статистически значимое улучшение. Значение CV в отчёте не переименовывается в pooled OOF.

## Запуск

1. Получить `train.csv`, `validation.csv` и `test.csv` со страницы соревнования и положить рядом с `solution.py`.
2. Создать Python-окружение и установить `python -m pip install -r requirements.txt`. Подойдёт Python 3.11; точная версия Python исходного запуска в ноутбуке не сохранена.
3. Выполнить `python solution.py` или открыть `solution.ipynb` в Jupyter с теми же зависимостями и запустить все ячейки.

Получится `final_submission.csv`. Код проверяет размеры данных, значения validation AUC, порядок строк и формат результата. Если рядом есть оригинальная отправка `submission_D_PCA128_LogPCA128_63_27_10.csv`, дополнительно проверяется совпадение предсказаний с допуском `1e-6`.

Данные, оригинальная отправка и готовые веса в репозиторий не включены. Полный запуск на данных соревнования при оформлении репозитория не повторялся. Код обучает зафиксированную финальную модель на train; исторический внешний CV и подбор параметров заново не запускаются.
